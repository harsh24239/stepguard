This is a recording plan, not evidence that these runs have happened. Record it only after the real model and kit gates pass. Keep the visible provider badge accurate; a Gemini recording is a development demo and does not establish Meta usage.

- **0:00–0:20 — Problem and scope.** Show the small assembly kit and its manual. Explain that StepGuard checks visible assembly steps from a manual and helps catch omissions before the next step. Call it a prototype; avoid continuous-inspection, compliance, or unmeasured accuracy claims.
- **0:20–0:45 — Manual to requirements.** Upload the actual PDF. Show the compiled instruction, visual part phrases, counts, anchor, and a supported spatial rule. Explain the actual compiler provider. Acknowledge the reviewed requirements and select Start inspection. Keep credentials and private account screens out of the recording.
- **0:45–1:20 — Missing part and lock.** Leave out a visible required part, capture the overhead image, and check the active step. Show the returned counts, overlay, specific correction hint, and the still-locked following step. Let the actual result determine narration. If unsure, show why it stayed locked and improve the evidence.
- **1:20–1:55 — Correction and progression.** Correct the assembly, then check again. Show a real pass and the next step unlocking. Keep the checked evidence visible, then select Continue to present the next task. Do not use a manual override to simulate an automatic pass. Demonstrate a placement error if the chosen checklist establishes that rule and time permits.
- **1:55–2:20 — Voice and automatic trigger.** Hold the microphone button, say “check step,” and show the actual recognized command initiating the same guarded check. Briefly demonstrate motion-stop checking if calibrated. Browser speech reads feedback; it is not a Meta voice-generation model.
- **2:20–2:45 — Technical depth and evidence.** Show the audit trail, then explain the anchor zone, counting, geometry, conservative judge, retries, and lock. Show measured comparison results only after running the evaluation with real labeled photos. Label the tested kit and sample size; include errors and false passes.
- **2:45–3:00 — Limitations and links.** State fixed-camera/single-kit prototype limitations and any observed uncertainty. Show the public repository and accessible product/video links. Identify the actual Meta models used and all collaborators in the submission fields.

Before recording, verify camera and microphone permissions, consistent overhead framing, lighting, live provider access, quota, and a readable manual.
